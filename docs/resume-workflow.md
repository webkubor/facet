# 简历生产流水线（质量保证流程）

> 原则：内容先于样式，规划先于渲染，每一步有验证门禁。每一条经历都要经得起 CTO 追问。

## 阶段一：看内容（事实调研）

- 简历素材必须来自**可验证来源**：真实项目代码、git 提交记录（`git shortlog -sne` 确认作者归属占比）、用户口述确认。
- 主导 / 参与 / 独立开发的措辞由 commit 占比决定：≥80% 可写「主导/独立」，明显非第一作者只能写「参与」。
- 记录「诚实红线」清单：哪些不能写（非本人代码、文档仓不算编码交付、复制分叉不能写成 monorepo）。

## 阶段二：内容规划（分模块）

- 按目标岗位定位组织章节（如支付方向 / AI 平台方向各一版），每版突出对应业务线，另一条线压缩为简版。
- 每个模块内部结构：架构与规模（可量化数字）→ 关键实现（具体技术方案）→ 结果。
- 禁止出现的内容：UI 框架选型这类无门槛工作、「熟悉 XX 技术栈」的罗列、无佐证的形容词。
- 首屏摘要 = 定位 + 三个最硬的数字；工作经历时间线 + 教育 + 个人特质放最后一节。

## 阶段三：选择样式模板风格

- 从 `templates/resume-*` 中按方向气质选择（支付暖色 payment-lead / AI 冷灰蓝 ai-platform 等）。
- 联系方式一律走 `.env` 注入（`${RESUME_CONTACT}`），源文件命名 `content/*.local.md`（gitignored）。

## 阶段四：分页规划

- **分页是量测驱动的**：构建时自动在真实模板 + 打印宽度下量测每张卡片像素高，按每页真实预算装箱（见 design-spec「空间利用规则」）。不存在任何需要手调的分页参数。
- 构建后跑 `pnpm verify:resume output/xxx.html`：页高（offsetHeight，print 媒体）、PDF 页数（解析页树，勿用 mdls）、标题行数、留白率、卡片间空洞、联系方式注入，六项全绿才算过。
- 留白超标的正解是**调整内容规划**（该页补一条有佐证的事实，或把某章节拆/并），不是调参数。
- 超高时的裁剪顺序：先删语义重复的条目 → 合并单条小节省卡片标题 → 压缩长句去从句，禁止删事实性数字。

## 阶段五：UI 优化（目检门禁）

- 全页截图逐页目检：首屏 10 秒能读出「姓名/定位/年限/联系方式/三个硬数字」。
- 检查项：文字与装饰背景对比度、页尾留白比例（末页除外不得超过 25%）、页面大标题不超过一行半、表格与代码不溢出。
- 快照卡（Selected Focus）描述自动取各章节第一条要点，所以每个 H2 后第一条 bullet 必须是该模块最硬的一句。

## 验证命令速查

```bash
# 打印宽度页高检测（794px 视口，clientHeight 必须 ≤ 1123）
# PDF 页数解析（/Type /Pages /Count，勿用 mdls）
# 详见 tmp/check-overflow.mjs 模式
```

# 公众号图文预览：版式与交付约定

**范围：本地同稿预览与静态导出。** 不做公众号后台、账号接入或群发。

```sh
facet --input article.md --wechat-preview --output output/article.wechat
```

稿件开头用 `title`、`digest`、`cover`（均必填）和 `author`（可选）。封面和正文图片用稿件目录内的 PNG、JPEG、GIF 或 WebP 相对路径，正文图用普通 Markdown 图片语法。正文支持标题、段落、列表、引用、加粗、代码和完整 HTTP(S) 链接；原始 HTML 不执行，首版不支持表格。示例：

```md
---
title: 第二天九点，报表到了吗？
author: 示例作者
digest: 同一版图文，分别检查卡片和手机正文。
cover: cover.png
---

这是首屏导语。

## 第一次任务

![示例图](body.png)
```

产物目录必须不存在，以免覆盖旧版。打开 `preview.html` 看卡片和正文；交给公众号项目的是 `article.html`、`manifest.json` 与 `media/`。预览和交付的正文字节在本地一致。公众号项目如接入，应验证正文和素材 SHA-256，再将已登记的正文图片地址映射成微信素材地址，单独用封面文件取得封面标识。**目前没有接入公众号项目或完成微信真机验收。**

## 目标

作者在本地检查手机正文和订阅消息卡片，再由公众号项目把同一版图文送到微信草稿箱。当前 `wechat-magazine` 仍是 PDF／长图模板，不把 A4 版式直接当作微信图文，也不改变已有模板的默认行为。

验收目标是**预览与提交使用同一版正文和素材**。最终显示以目标公众号的微信手机预览为准；不同设备、字体设置，以及微信自己的标题、卡片裁切和页面按钮，不在本地逐像素一致的承诺内。

## 谁负责什么

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 写作 Skills | 选题、读者背景、观点和正文自查 | 公众号 HTML 和手机视觉验收 |
| Facet | 手机正文版式、卡片模拟、可交付的 HTML 和素材清单 | 写稿、生成图片、账号、平台操作 |
| 公众号业务项目 | 提供定稿与配图、上传素材、入草稿箱，回读并在手机微信验收 | 二次排版或静默更换稿件 |
| 调度层 | 记录负责人、进度与验收状态 | 持有稿件、样式、素材、账号和发布逻辑 |

本仓只放通用工具、规范和合成示例。用户文章、照片、账号、凭据和真实草稿记录不进入公开仓库。

## 交付约定

1. **同一份正文，两种用途。** 从 Markdown 和明确的标题、作者、摘要、封面、插图生成一份内联样式 HTML。手机预览直接嵌入这一份正文；手机框、卡片模拟、公众号页眉样品都在正文之外，不进入提交内容。
2. **只有素材地址可以映射。** 交付清单记录正文与素材版本。公众号项目上传同一组素材后，只替换预览素材地址为微信可用地址，不再重新渲染段落样式。封面单独核素材标识和裁切。缺图明确报错，不用占位假装齐了。
3. **两套验收各自留证。** 本地验收文章、窄屏与卡片；公众号项目在对应微信草稿回读后，用手机微信的「预览」验收。改动标题、摘要、封面、正文、素材或版式之后，旧结果不沿用。未跑第二关只标「本地预览」，不标「微信已验收」。

## 通过标准

- 用一篇公开安全的合成示例：中文标题、两级正文结构、加粗、引用、列表、封面和两张正文图。
- 在 360 与 390 CSS 像素宽度检查首屏、段落、行距、重点、图片顺序和无横向溢出。卡片与正文分开检查。微信应用外观的模拟项显式标注。
- 比较本地正文与待提交 HTML：除按清单映射的图片地址，正文结构、文字顺序和内联样式一致。异常素材和已修改的版本不能标为通过。
- 用同一版草稿在目标公众号的手机微信里检查字号、换行、图文顺序、封面和首屏。网络或账号不可用时保留为待验。入箱或模拟截图不等于实机验收，更不等于已发布。
